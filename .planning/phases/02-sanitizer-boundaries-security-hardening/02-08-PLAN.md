<objective>
Make push verify, before publishing, that every parameterized file renders back to exactly the local text through the same renderer and render rule that init, scan and pull use (SEC-04; RESEARCH Pattern 4; orchestrator item 2). Push refuses the file otherwise.

Purpose: parameterization can turn a valid file into an unrenderable or different template. The shipped commit-msg hook's `${#FIRST_LINE}` becomes a Jinja comment opener as soon as a `{{ user.home }}` is inserted (minijinja 2.24.0: `syntax error: unexpected end of comment`). One such push would break `ude sync pull` and `ude init` for every consumer. A string-replace inverse would report "reversible" for exactly those cases, so the check must use the real renderer. Pull's refuse-on-error pattern is the model, not scan's swallow-on-error.

Output: gate 5 in push_updates with a new `PushResult::ReversibilityBlocked` and its CLI arm (exit 1), scan and pull moved onto `template::should_render`, sync and e2e tests, and the Phase 1 hermeticity gate re-run as the phase's last gate.
</objective>
