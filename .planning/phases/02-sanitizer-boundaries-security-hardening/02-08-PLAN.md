<objective>
Make push verify, before publishing, that every parameterized file renders back to exactly the local text through the same renderer and render rule that init, scan and pull use (SEC-04; RESEARCH Pattern 4; orchestrator item 2). Push refuses the file otherwise (kept by operator decision OD-2, 2026-10-25). The refusal names a fixed error category and a line, never the engine's detail text (review concern 4). The publication gates then bind the blobs git stores to the fingerprints of the bytes push validated, carried from push_updates, so a clean filter or commit hook cannot publish something the checks never saw, even when it rewrites the working tree too (review concern 3, checker revision 1).

Purpose: parameterization can turn a valid file into an unrenderable or different template. The shipped commit-msg hook's `${#FIRST_LINE}` becomes a Jinja comment opener as soon as a `{{ user.home }}` is inserted (minijinja 2.24.0: `syntax error: unexpected end of comment`). One such push would break `ude sync pull` and `ude init` for every consumer. A string-replace inverse would report "reversible" for exactly those cases, so the check must use the real renderer. Pull's refuse-on-error pattern is the model, not scan's swallow-on-error. Git runs clean filters during `git add` (src/sync/mod.rs:1659-1674), after the check, so the check alone would protect bytes git may replace.

Output: gate 5 in push_updates with a new `PushResult::ReversibilityBlocked` and its CLI arm (exit 1), `TemplateRenderer::render_str_checked` with a content-free `RenderFailure`, scan and pull moved onto `template::should_render`, blob-to-file binding in both publication gates, sync, template and e2e tests, and the Phase 1 hermeticity gate re-run as the phase's last gate.
</objective>
