<objective>
Make path parameterization respect word and punctuation boundaries on both sides (SEC-03) and prove the parameterize-then-render round trip at sanitizer level (SEC-04).

Purpose: today's boundary class `[/\\"'\s:]` misses `)`, `,`, `;`, `}`, a sentence-final `.`, and anything after a leading `-` (`${W:-/home/alice/...}`, a shape the operator's own template uses). So the pusher's home path, and with it the username, is published into shared templates (the pending todo "Home-path placeholders leak the pusher's home path"). A literal regex `\b` is wrong for paths that start with `/`, and the `regex` crate has no look-around (RESEARCH Pattern 3, orchestrator item 3). The fix is a hand-written boundary predicate over `str::match_indices`.

Output: rewritten parameterize_paths with four small helper functions, a push-level tracer test, boundary-table, degenerate-home, encoding and property tests, a scoped mutation gate, and a corrected placeholder list in docs/ARCHITECTURE.md.
</objective>
