<objective>
Close verification gap 1 (review CR-01, SEC-03 prohibition of plan 02-07): when HOME or XDG_CONFIG_HOME ends in a path separator, home-path parameterization rewrites nothing and `ude sync push` publishes the pusher's raw home path while reporting success. Normalize trailing separators off the home and XDG config roots, keeping a root made only of separators as it is so the degenerate-root guard still rejects it, in parameterize_paths' caller (push_updates) and in TemplateContext::detect_for_project, so render and parameterize stay in sync.

Purpose: dirs-sys 0.5.0 `home_dir` returns `$HOME` as given and directories 6.0.0 takes `XDG_CONFIG_HOME` as given, so `HOME=/home/alice/` yields the needle `/home/alice/`. replace_bounded then never matches: `/home/alice/x` has an alphanumeric after the needle and `(/home/alice)` lacks the trailing `/`. Gate 5 compares unchanged text to itself and passes, so nothing refuses the raw path. One helper, applied where the roots are consumed, fixes push; the same helper in detect_for_project keeps init, status and push's scan rendering placeholders with the spelling push parameterizes with (otherwise init writes `{fake}//.gitconfig.local` and a pushed file reads as drifted).

Output: `sanitizer::normalize_root`, its use in push_updates, detect_for_project and parameterize_paths, sync unit tests, two CLI e2e tests, boundary-table and property rows over root spellings, and a scoped mutation check.
</objective>

## Decisions and assumptions recorded here

- Scope: exactly verification gap 1 (`gaps:` entry 1 of 02-VERIFICATION.md). Review WR-01 (raw home after parameterization), IN-01 (silent skip of an unparameterizable root) and WR-02 (merge HEAD at the commit gate) are not in the verification gaps and are not planned here.
- Planner decision (fix direction given by the gap): one helper, `sanitizer::normalize_root`, next to is_parameterizable_root (the predicate it feeds), used in three places. push_updates is parameterize_paths' only production caller and also builds gate 5's render context, so normalizing there keeps the two in one spelling for every caller. parameterize_paths normalizes too, so its own contract (and the boundary table the gap asks for) holds for any caller. detect_for_project normalizes so init, status, pull and push's scan render with the same spelling. Reversibility: reversible (one function, three call sites).
- Planner decision: src/main.rs is not changed. The Sync command's user_home and xdg_config reach only push_updates and the cache-dir fallback; normalizing at push_updates covers the CLI and every test caller, and the e2e tests run the real CLI with HOME and XDG_CONFIG_HOME ending in `/`. VERIFICATION lists main.rs:724-727 as where the raw value is read, not as the only place a fix may live.
- Planner decision: separators are `std::path::is_separator` (`/` on Unix; `/` and `\` on Windows). On Unix a trailing `\` is a file-name character and is kept (test row). Windows behaviour is unverified (Phase 999.1).
- Planner decision: xdg_data in detect_for_project is not normalized. Push never parameterizes it and the gap names the home and XDG config roots only; a trailing separator in XDG_DATA_HOME can still render `//` through `{{ user.xdg_data }}` (cosmetic, pre-existing, no publication path).
- What this does not establish: only trailing separators are normalized; `/home/alice/.`, `/home//alice` and symlinked or alias homes are not (T-02-33). The e2e tests use one HOME layout under the test's temp dir; they show the CLI path normalizes, not every HOME a user could set.
