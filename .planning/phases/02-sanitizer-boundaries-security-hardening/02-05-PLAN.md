gitleaks v8.30.1 detect/detect.go, read at plan time (plain-text path, no decoding):
- per rule: a rule-allowlist path pre-check skips the rule for the file when an OR allowlist's `paths` match, or when an AND allowlist with no regexes and no stopwords has all its defined checks true; `path` + no regex is a path-only finding; `path` + regex returns early when the path does not match.

- entropy: `if r.Entropy != 0 && shannonEntropy(secret) <= r.Entropy { continue }`. shannonEntropy (detect/utils.go:117-134 at v8.30.1, re-read at plan revision) is standard Shannon entropy: it counts each distinct rune, sets freq = count / len(data) (Go's `len` of a string is its byte length), and returns −Σ freq·log2(freq). For an ASCII secret runes are bytes, so this equals −Σ p_b·log2(p_b) over byte frequencies. It is not the distinct-count ratio, which never exceeds 1.0 and would skip every entropy-gated rule (130 of the 222 rules set `entropy`, counted at plan revision in the pinned file).
- `checkFindingAllowed`, global allowlist first, then rule allowlists: target = secret (default), Match (`match`) or Line (`line`); OR: regexAllowed(target) || containsStopword(lower(secret)); AND: every defined check among paths, regexes and stopwords must hold.
- `gitleaks:allow` in the line skips a finding in gitleaks; UDE must not do this (D-03).

## Decisions and assumptions recorded here

- Claude's discretion (secret rule source), settled per RESEARCH: embed the pinned gitleaks rule file and port its semantics. Shelling out to the gitleaks binary was rejected: it is a Go runtime dependency on every machine, and policy item 6 would then make push impossible wherever it is missing. A hand-picked subset was rejected: it cannot claim the full categories.
- Assumption A3 (RESEARCH): gitleaks' encoded-segment decoding (base64/hex/percent-encoded secrets inside other text) is not ported. R11 catches most encoded blobs; a short base64-wrapped secret that fails R11 is missed. Documented gap, accepted (T-02-17 in plan 02-06).
- Assumption A4 (RESEARCH, extended): the global allowlist's `paths` are not honoured, so no file is ever skipped whole (fail closed). Rule-level allowlist paths are honoured.
- Planner decision: the port's Shannon entropy is −Σ p_b·log2(p_b) over byte frequencies, p_b = count / byte length. gitleaks computes the same sum over rune counts with the same byte-length denominator (detect/utils.go:117-134, re-read at plan revision), so the two are equal for ASCII secrets; for non-ASCII secrets gitleaks counts runes. Because of the ASCII-mode regexes such secrets are rare. A separate private function is kept in gitleaks.rs instead of sharing entropy.rs's, because plan 02-04 edits entropy.rs in the same wave.
- Planner decision: `first_finding` reports the first rule in file order that has a finding; only blocking matters here, and gitleaks' own report ordering is not reproduced.
- **Flagged assumption (edge probe, unclassified):** the spec-less edge probe could not classify SEC-02; beyond the truths above (strict entropy floor, LF trimming, empty-path wrapper, path-only line 1), no edge predicate was generated. Review manually.
