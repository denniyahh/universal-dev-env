## The closed list

**Scope.** Code running in the cache checkout (a hook, including one that global or system `core.hooksPath` names; a filter; a config-defined command; or a process one of them left) writing state in that checkout's own repository (`.git`: hooks, config, refs, index, objects, info, shallow) while `ude sync push` runs through `ensure_remote_repo_for_push` and `push_to_remote`. Global and system git config is outside this scope except where a row below names a key of it.

**What was run.** Every test named below runs against a remote reached by a local path or file URL, with git 2.56.0 on Linux. NOT-12 lists what was not run; not run is not the same as not defended.

**The promises, within that scope.**

1. What is sent: UDE's push sends the validated commit: exactly one commit on the remote's head as read from outside the checkout, whose tree is the tree UDE staged, whose message is the sync message, and whose changed blobs are the validated bytes, and no object outside it; apart from two cases pending the operator (NOT-10): a `.git/shallow` file written after the gate, and a loose object file overwritten during the push after the gate read it.
2. What Ok means: Ok after a push means the caller's URL, read from outside the checkout, reports the target ref at that commit. Ok with nothing to push means the head read that way holds every recorded path and none of the deleted ones.
3. What a refusal prints: the committed gate's refusals print no bytes a hook chose, apart from a failed git command's stderr excerpt (NOT-09).

**Classifying a later finding.** Each finding gets exactly one of three outcomes. (1) It names a channel in a DEF row, shows that row's outcome failing on any transport or platform, and fits no NOT row: a defect, which re-opens that row. A class row holds for every instance of its class, so a new instance of DEF-01, DEF-06, DEF-12 or DEF-13 that fits no NOT row is a defect, not new scope. (2) It names a channel and outcome in a NOT row and fits no DEF row's failing outcome: not a finding; the row's status stands until the operator changes it. NOT-12 records runs that do not exist, so it never decides a finding under (2) and never stops one under (1). (3) Anything (1) and (2) do not decide goes to the operator: a finding that names neither kind of row, or one that fits both a DEF row and a NOT row, a new instance of a class row included. Record it and ask the operator whether it joins the DEF rows or the NOT rows, or which of the two rows holds. It re-opens nothing, and it does not join either list by default.
