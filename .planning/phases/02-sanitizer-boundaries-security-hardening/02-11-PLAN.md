<objective>
Close the last verification gap of phase 02 (02-VERIFICATION.md `gaps:` entry 1; review WR-102; SEC-04). Plan 02-08's prohibition "never publish a blob differing from the validated bytes, whatever git clean filter or commit hook produced it" fails today: validate_committed_tree lists `git diff-tree -r HEAD`, which is empty for a merge (and for an empty commit), and the only ancestry check (check_continuity, direct mode only) looks at HEAD's first parent. A post-commit hook that amends UDE's commit and wraps it in a merge whose first parent is the fetched head gets its content to the remote; in PR mode there is no ancestry check at all.

Operator decision (2026-10-27/28, explicit): fix the gap, do not override it. Approach chosen here (see Decisions): bind the published commit to the fetched head in both modes (exactly one parent, read from the raw commit object; changes listed from the fetched head), read every committed object raw, and push the validated commit id with no tags following (`--no-follow-tags`, operator decision 2026-10-28). Running the commit with hooks disabled was rejected on evidence.

Split (DECIDED, operator, 2026-10-28): this plan is the first half of the gap closure. Plan 02-12 (wave 9, depends on this plan) carries the rest of the same SEC-04 prohibition: the commit message bound to SYNC_COMMIT_MESSAGE, the header secret scan and the empty-directory refusal, the grafts refusal, commit-graphs and bitmaps disabled on both pushes, the scoped mutation run and the phase's final gates. Plan 02-08's rule in full (every object the push sends) holds only after 02-12, and then with the one exception the operator accepted on 2026-10-28 and plan 02-12 records: a grafts file a pre-push hook writes during the push (T-02-52).

Purpose: the publication gates are the last defence between a validated file and the shared template repository; a hook in the cache checkout (global `core.hooksPath`, `.git/hooks`, or a config-defined hook) must not be able to put unvalidated bytes into the history the push publishes.

Output: the bound committed gate and push in src/sync/mod.rs, the verifier's reproduction plus a PR-mode variant as RED tests, boundary/precision/control tests, one raw-object test per gate read (blob, commit, tree), a validated-id push test, a tag-following test per push mode, and the plan-end gate (fmt, clippy, targeted tests).
</objective>
