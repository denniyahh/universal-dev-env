<objective>
Make the sync unit tests and the e2e tests hermetic with respect to git: fixture git commands must ignore an inherited GIT_DIR / GIT_INDEX_FILE / GIT_CONFIG etc., must not depend on the host's git identity or system config, and must fail loudly when a fixture step fails (Wave 0 gap in 01-VALIDATION.md, research Pitfall 10).

Purpose: today 6 sync tests fail when GIT_DIR points at a decoy repo, and fixture steps such as `let _ = <git ...>.status()` silently produce meaningless tests. SYNC-03's isolation guarantees (plan 01-03) cannot be verified on a non-hermetic suite. This plan fixes the test side; plan 01-03 fixes the production side and then runs the combined hermeticity gate.

Output: `GitFixture` helper in the `mod tests` of src/sync/mod.rs and a copy in tests/e2e_lifecycle.rs; all existing fixture git spawns converted.

Scope note: this plan touches only the `#[cfg(test)] mod tests` region of src/sync/mod.rs (starting at the `mod tests {` line, about line 1229). Production code in that file is untouched here, which is why it can run in wave 1 beside plan 01-01.
</objective>
