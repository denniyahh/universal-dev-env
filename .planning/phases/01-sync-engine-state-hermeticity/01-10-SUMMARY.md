# Phase 01 Plan 10: Conflict Resolve Command and Push Skip Reporting Summary

**`ude sync resolve <file>` now ends a conflict offline: the file's current local state becomes the resolution against the upstream version pull recorded, following state table outcomes R1-R4. Push no longer aborts on the first conflict or silently ignores merged files. It publishes every eligible file, skips unresolved conflicts and unpulled clean merges, prints the command to run for each, and exits 1.**

## Accomplishments
- `SyncAction::Resolve { file }` and `SyncEngine::resolve_conflict`. R1 (recorded upstream, local present): `KeptLocal`, ancestor := recorded upstream, so the next push publishes. R2 (local absent): `AcceptedLocalDeletion`, so the next push deletes the template. R3 (upstream deleted, local present): `KeptUnmanaged`, a tombstone with `kept_unmanaged = true` that push never republishes. R4 (both absent): `DroppedDeleted`, with a tombstone only when a files record supplies a fingerprint.
- Resolve order: state is staged, then the sidecar is removed, then state is committed. A symlinked, directory or unremovable sidecar returns an error naming it, with state.json byte-identical and the conflict still open. Path validation (only normal components, only `MANAGED_FILES`) runs before state is loaded.
- `main.rs`: the remote setup (`ensure_remote_repo` and the lock) moved into `open_sync_templates`, which only status, pull and push call. Resolve is the first arm and needs no network. There is no unreachable arm.
- `push_updates`: `Conflicted` and `ConflictPending` go to `skipped_conflicts`, `Merged` to `skipped_merged`. `PushResult::ConflictBlocked` is gone. The CLI prints `<file>: unresolved conflict, skipped (run ude sync resolve <file>)` or `<file>: merged with upstream changes, skipped (run ude sync pull first)`, publishes the rest, then exits 1.

## Decisions Made
- **Resolve errors all exit 2**, including sidecar and state-write failures (the plan specified exit 2 for invalid targets and EXIT_HARD_FAILURE for every Err).
- **Path normalisation:** the accepted path is the `MANAGED_FILES` entry itself, so `mise.toml/` style spellings resolve to the canonical path. `./mise.toml` is refused as a non-normal component, which the plan's rule implies.
- **Skip lines go to stderr** (like pull's conflict lines); the e2e checks both streams.
- **The existing push line `Successfully synchronized N file(s) into upstream template store.` was kept** instead of a new `Synchronized N file(s)` line, because it already states the count. When everything is skipped it reads 0.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The `resolve_conflict` signature grep conflicts with the fmt gate**
- **Found during:** Task 1 acceptance
- **Issue:** the plan's single-line `rg` pattern needs the signature on one line, which is 101 columns. rustfmt's limit is 100, so `cargo fmt` wraps it, and `cargo fmt --check` is the real gate.
- **Fix:** kept the rustfmt layout and verified the same signature with a multiline pattern: `rg -U -c 'pub fn resolve_conflict\(\s*&self,\s*local_root: &Path,\s*rel: &Path,?\s*\) -> Result<ResolveOutcome, String>'` returns 1.
- **Committed in:** 40edc7f

**2. [Rule 2 - Hermeticity] New e2e spawns drop the host TypeSafe key**
- **Found during:** Task 2 RED. The first run printed `TypeSafe System One (Jev) enabled`, so the test binary saw the host's `TYPESAFE_API_KEY`.
- **Fix:** `sync_cli` calls `env_remove("TYPESAFE_API_KEY")`. Re-running showed no TypeSafe line. The pre-existing spawns are logged in `deferred-items.md` (scope boundary).
- **Committed in:** ded813d

**3. [Rule 2 - Test strength] Extra cases beyond the plan**
- A symlinked managed file is refused with state unchanged (`test_resolve_rejects_invalid_targets`); this caught the "symlinked local read as absent" mutant. Also `./.gitconfig` and an absolute path outside the project as invalid targets, a byte check that push leaves every local file unchanged, and a resolve-then-push negative control in the e2e.
- **Committed in:** ded813d, acef827

**4. [TDD order] Deletion branches implemented in Task 1's GREEN**
- See TDD Gate Compliance. No production change was made in Task 3.
