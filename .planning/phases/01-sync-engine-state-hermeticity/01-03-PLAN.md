## Decisions and assumptions recorded here

- D-03 / D-04 implemented as specified. The hermeticity gate additionally sets GIT_CONFIG_GLOBAL=/dev/null and GIT_CONFIG_NOSYSTEM=1 (stronger than the research gate) so no sync test can lean on the host identity.
- Revision 2026-10-18 (external review, timing headroom): test_push_timeout_hanging_hook's hook sleeps 20 s (was 10 s) and the bound is 8 s (was 5 s). That leaves at least 4.5 s of headroom for a correct run on a loaded build host and 12 s between the bound and the unbounded case. The 1.5 s network limit and the asserted message are unchanged.
- `ProcessLimits` / `with_limits` exist only so tests can use sub-second limits; there is no config or env override (CONTEXT Deferred Ideas: timeout overrides).
- Assumption A2 (research): `git gc --auto` daemonizes with setsid and is unaffected by group kill; worst case an auto-gc in the cache checkout is cut short and re-runs later.
