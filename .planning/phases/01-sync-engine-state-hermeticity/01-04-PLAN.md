<objective>
Make the state ledger fail loudly instead of silently resetting (D-06), refuse state files from a newer ude (forward guard per the operator's D-07 decision), write state.json atomically (D-05), and introduce the named exit codes this phase uses (1 drift/conflict, 2 hard failure).

Purpose: today a corrupt or unreadable `.ude/state.json` is replaced by empty state, which turns every managed file into "no ancestor" and invites false conflicts or republishing. Every later plan in this phase (schema version bump, staging, deletions, conflicts) depends on state errors surfacing and on state being written atomically and last.

Output: Result-returning load with forward guard, staged/atomic save, scan_project returning Result, exit-code constants and mapping in src/main.rs, e2e test for corrupt and future-version state.
</objective>

## Decisions and assumptions recorded here

- D-06 implemented as specified. D-05 applied to state.json here; workspace files in plan 01-06.
- Operator decision on D-07 (2026-10-17): forward-version guard added; no older ude binaries run elsewhere. **Accepted limitation:** ude binaries built before this phase cannot be made to fail loudly on a newer state.json (they ignore unknown fields and fall back to empty state on parse errors); "older binaries fail loudly" holds only for binaries built from this phase onward.
- Exit-code scope: only the sync dispatch outcomes this phase touches are mapped (1 = conflict/drift/skipped, 2 = hard failure). SecretBlocked / BoundaryBlocked / TypeSafe policy shift keep their current exit 1 until CLI-04 (Phase 3). `ude sync status` still exits 0 on drift.
- <reversibility> of the exit-code split: costly. Scripts and agents will branch on 1 vs 2; CLI-04 in Phase 3 builds on the same contract.
